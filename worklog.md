Work Log:
- Design decision — FTS flavor: standalone (contentful) FTS5 table `circuits_fts(name, description, tags, circuit_id UNINDEXED)` maintained by the app (delete+insert per circuit), chosen over external-content (needs an integer content_rowid; saved_circuits PK is a TEXT uuid and the implicit rowid is invisible to Drizzle) and over contentless-delete (`content=''` requires the special 'delete' command with the exact previously-indexed values and SQLite >= 3.43; easy to corrupt). Plain DELETE-by-circuit_id + reinsert is trivially correct and idempotent; storage duplication is only name+description+tags (never the big `document` JSON). Rationale documented in the migration SQL + schema.ts.
- Design decision — case policy: `parseTags()` (new src/lib/tags.ts) splits on commas and/or whitespace, trims, dedupes case-insensitively and preserves the FIRST spelling for display; `normalizeTag()` lowercases for storage in circuit_tags and for query comparison (exact + case-insensitive without collations). The `saved_circuits.tags` TEXT column is KEPT as the source of truth (display/export/back-compat) and is canonicalized on write (`parseTags(x).join(', ')`) so TEXT and circuit_tags can never disagree.
